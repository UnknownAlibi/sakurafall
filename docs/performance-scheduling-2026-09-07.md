# 目录解析与播放期间后台调度

本轮实现：

- 超过 256 KiB 的目录 JSON 使用 Node Worker 解析，每批 200 条按确认消息回传，避免主进程一次接收完整对象树。小增量继续直接解析。切换连接方式会取消 Worker，保留原有 config_changed 返回协议。
- 封面缓存未命中下载共享全应用队列，并发上限 6、同站点上限 2、等待上限 240。缓存命中直接返回，相同封面复用已有请求，失败释放槽位。
- 主进程广播播放窗口存在状态。主窗口暂停低优先级刷新、元数据补全、下一页预取；可见封面仍经独立封面队列加载。最后一个播放窗口退出才恢复后台任务，初始状态查询带事件版本保护。
- 移除关窗时主动调用 global.gc 的旧路径，避免显式 GC 暂停。

验证：

- npm run verify 通过；新增解析、取消、按站点调度与多播放窗口行为测试通过。
- npm run lint：0 错误，SubjectService 的原有 unused refresh 警告仍在。
- Windows Electron 打包成功；scripts/smoke-playback-pressure.js 实测开关窗口事件为 [true,false]。本机使用显式 --no-sandbox 测试参数，未更改应用默认启动安全配置。
- scripts/bench-snapshot-parser.js：55,976,766 字节合成 JSON、29,015 条。直接解析总耗时 40.4 ms，采样最长事件循环延迟 50.7 ms；Worker 分批解析总耗时 148.1 ms，最长延迟 26.8 ms。这是合成样本，不等同于真实目录导入或高刷新率滚动验收。

- S4 跨模块请求取消、共享请求消费者取消、离屏/可见封面优先级提升、队列超时与防饥饿尚未完整实现。当前 FIFO 封面队列仅解决无限并发和同站点阻塞。
