# 目录解析与播放期间后台调度

本轮实现：

- 超过 256 KiB 的目录 JSON 使用 Node Worker 解析，每批 200 条按确认消息回传，避免主进程一次接收完整对象树。小增量继续直接解析。切换连接方式会取消 Worker，保留原有 config_changed 返回协议。
- 封面缓存未命中下载共享全应用队列，并发上限 6、同站点上限 2、等待上限 240。缓存命中直接返回，相同封面复用已有请求，失败释放槽位。
- 主进程广播播放窗口存在状态。主窗口暂停低优先级刷新、元数据补全、下一页预取；可见封面仍经独立封面队列加载。最后一个播放窗口退出才恢复后台任务，初始状态查询带事件版本保护。
- 移除关窗时主动调用 global.gc 的旧路径，避免显式 GC 暂停。

验证：

- npm run verify 通过；新增解析、取消、按站点调度与多播放窗口行为测试通过。
- npm run lint：0 错误，SubjectService 的原有 unused refresh 警告仍在。
- Windows Electron 打包成功；scripts/smoke-playback-pressure.js 实测开关窗口事件为 [true,false]。本机使用显式 --no-sandbox 测试参数，未更改应用默认启动安全配置。
- scripts/bench-snapshot-parser.js：55,976,766 字节合成 JSON、29,015 条。直接解析总耗时 40.4 ms，采样最长事件循环延迟 50.7 ms；Worker 分批解析总耗时 148.1 ms，最长延迟 26.8 ms。这是合成样本，不等同于真实目录导入或高刷新率滚动验收。

## 2026-09-08 补充实现与复验

- 封面请求采用窗口内独立 requestId，取消消息只能操作同一 webContents 的请求。跨窗口共享一次下载，最后一个消费者离开才中止底层 HTTP 请求；窗口销毁、渲染进程退出、主框架导航均撤销所属请求。
- 当前可见封面优先，IntersectionObserver 在进入/离开视口时调整优先级。队列等待上限 20 秒、底层下载总时限 25 秒、等待任务按时间提升优先级，保留全局 6、同主机 2、排队 240 的限制。
- 渲染端不再另排一个无法取消的 FIFO 队列；主进程统一限制并发。组件卸载/换图会取消消费者，清空 memo 会撤销旧请求，迟到结果不能重建过期 memo。失败不再永久缓存原始 URL。
- 滚动、窗口隐藏、打开播放器的后台压力合并后通过 IPC 通知封面队列。暂停尚未开始的离屏持久化工作，但不暂停当前可见封面；恢复仍受并发上限约束。已在运行的共享请求不强制抢占。
- 后台调度器支持运行任务的 AbortSignal 和逻辑取消；实际任务未退出前不提前释放并发槽，旧任务清理不能删除同 key 的新任务。详情弹窗和列表详情补全已接入独立 requestId 的跨 IPC 取消；Bangumi/AniList 详情请求跟随 signal，主动取消不再触发镜像重试或健康扣分。多个消费者共享详情时，只有最后一个离开才中止底层请求。
- 目录导入期间用独立 WAL 只读事务固定列表读取视图，主写连接继续分批写入。导入完成或失败都关闭只读连接；持久化本地内容修订号，避免部分导入后沿用旧分页版本。失败不推进服务端成功游标，不删除用户数据。批次已落盘的数据不会整体回滚，重试使用保留的成功游标。
- 快照正式同步改为二进制 HTTP 响应；独占 Buffer 转移给 Worker，在 Worker 内解码并校验全部条目。主进程通过异步迭代器每次申请 200 条，写库后才申请下一批，不再汇总完整 subjects 数组。退出迭代、切换配置和异常均释放 Worker。原收集式解析器仅保留为兼容工具及对照基准。

仍需保留的验收边界：

- Worker 仍持有完整 JSON 输入和解析对象，尚非流式 JSON 解码；已经消除主进程第二份完整对象树。隔离 Node 导入峰值已测，完整 Electron 冷启动同步峰值仍需采集。

- 按实际返回条数推进扫描游标，不再假定上游一定接受请求的 pageSize。新增总数变化、空页、超量页、非法或重复 ID 的检查。
- 所有分类完整扫描后才合并发布；失败时丢弃暂存扫描，不推进成功时间、不发布半份预热结果。扫描期间新收到的详情优先，不能被旧页面覆盖。此改动不删除已有目录条目。

## Anime4K 长时间复验

- 最新 Windows 打包应用完成 300 秒运行，全屏、拖动、切集、暂停恢复各触发 11 次；没有记录交互异常。245 次有效像素采样全部变化，黑帧为 0，后端始终为 `webgpu-worker`，结束时 balanced、单帧约 4.05ms。
- 发现旧探针先过滤稳态样本再配对，跨交互累计时间，并把短片循环回绕当成零播放进度，导致原报告的 0.361x 稳态速率失真。新增独立统计函数和回归测试，只配对原始序列中相邻的稳态样本；跨交互不拼接，负媒体时间差显式排除。原报告未覆盖，新统计单独写入 `artifacts/anime4k-adjacent-timing.json`。
- 同一批原始样本重新统计：有效稳态媒体区间 95.034 秒，播放速率约 1.000x；CNN 计数测得约 22.76 fps（计数测量区间 119.938 秒）。这仍略低于 24fps 的 95% 门槛 22.8fps，且采样间隔最高 1.115 秒，不能证明不存在 500ms 短冻结。
- 因而 S2 保持未完全验收。下一步需要更细粒度帧时间采样和至少 60 秒不循环样片，不能把当前长测的“无黑帧、画面持续变化”等同于所有实时增强指标达标。
